# RAG 检索评测说明

> 目的：让「召回参数」和「检索效果」可量化、可回归，而不是拍脑袋调 `topK` / 相似度阈值。
> 评测集：[`src/test/resources/eval/aftersales_eval.jsonl`](../../src/test/resources/eval/aftersales_eval.jsonl)（40 条）

## 1. 评测集构成

| 维度 | 说明 |
|---|---|
| 总量 | 40 条：35 条可回答 + 5 条应转人工 |
| 覆盖 | 3 份知识库文档、14 个规则小节（退换货 5 / 物流 5 / 商品与价保 4） |
| 分类 | 退换货 10、物流 10、价保 5、发票 4、赔付 3、质量 3、转人工 5 |
| 标注 | 每条含：问题、期望文档、期望小节、期望关键句（检索片段需包含该句才算命中） |
| 自检 | `EvalDatasetTest` 离线校验结构，并逐条检查关键句确实存在于知识库 |

## 2. 指标定义

- **hit@k**：前 k 条召回结果中包含期望关键句的比例；
- **MRR@8**：首个命中排名的倒数均值；
- **转人工空检索率**：5 条域外问题返回 0 条结果的比例（越高越好，代表不硬答）。

## 3. 运行方式

```bash
# 1) 离线自检（无需 Key，CI 可跑）
mvn -o test -Dtest=EvalDatasetTest

# 2) 真实检索评测（需 application-local.yml 配置 DashScope Key）
RUN_RETRIEVAL_EVAL=true mvn -o test -Dtest=RetrievalEvalTest
# 报告输出：target/eval/retrieval-report.md
```

## 4. 当前结果（2026-11-12，topK=4 / threshold=0.4）

| 指标 | 数值 |
|---|---:|
| hit@1 | 88.6%（31/35） |
| hit@3 | 97.1%（34/35） |
| hit@4 | **100%（35/35）** |
| MRR@8 | **0.9310** |
| 转人工空检索率 | 80%（4/5） |

阈值扫描（topK=4）：`0.30 → 100% / 40%`，`0.35~0.40 → 100% / 80%`，
`0.45 → 97.1% / 80%`，`0.50 → 91.4% / 80%`，`0.55 → 82.9% / 100%`。

**结论**：当前 `topK=4 / threshold=0.4` 已位于最优区间——再提高阈值会开始丢召回
（0.45 起 hit@4 下降，0.5 掉到 91.4%），再降低阈值会让域外问题更容易被硬答。
完整报告见 [`retrieval-report.md`](./retrieval-report.md)。

## 5. 已知局限与改进方向

1. **1 条转人工误召回**：「快递员态度差，我要投诉」与物流规则语义相近，仍会召回 4 条；
   应补一层「规则未覆盖时（投诉/主观评价）强制转人工」的意图分类或提示词约束。
2. 评测只覆盖**检索环节**，尚未覆盖「答案是否忠实引用原文」；下一步可加引用正确率与人工抽检。
3. 关键词元数据（`MyKeywordEnricher`）目前只入库未参与过滤，可在召回不足时用于兜底过滤。
