## 2. 关键设计决策

- **流式聚合放在 Agent 层而不是框架层**：Spring AI 的 `MessageAggregator` 只聚合文本、不聚合工具调用，
  因此由 `ToolCallAgent.StreamCollector` 同时聚合文本与工具调用分片；token 事件由 `BaseAgent` 统一下发。
- **token 推送不能用 ThreadLocal**：模型 SDK 的增量回调发生在 IO 线程，ThreadLocal 会取不到 SSE 连接；
  改为实例字段（`streamEmitter`），并约束“同一实例同时只支持一个流式会话”（Controller 每次请求新建实例）。
- **多轮会话用实例池而不是手工拼消息**：保留 Agent 内部 `messageList`（含 tool_use/tool_result 配对），
  避免手工截断导致 Anthropic/DashScope 消息协议不合法。
- **评测先于调参**：先量化 hit@k/MRR/转人工空检索率，再决定阈值；结论是当前参数已最优，不为了“有提升”硬调。

## 3. 已知问题

1. **MCP 客户端接入实验性失败**：MCP 服务端 SSE/stdio 均可启动并注册 1 个工具；
   主工程作为客户端接入时，`McpSyncClient.initialize` 20s 超时（Spring AI 1.0.0 / MCP SDK 0.10.0），
   已保留 `application-mcp.yml` 与配置文档，待升级或改 streamable HTTP 传输后验证。
2. 1/5 转人工问题（快递员投诉）仍被召回 4 条：语义接近物流规则，需意图分类或提示词约束。
3. 会话/向量库为单机内存实现，重启丢失。

## 4. 复现命令

```bash
mvn -o test                              # 离线全量测试
mvn -o test -Dtest=EvalDatasetTest       # 评测集自检
RUN_RETRIEVAL_EVAL=true mvn -o test -Dtest=RetrievalEvalTest   # 真实检索评测（需 Key）
cd ecom-frontend && node tests/run.mjs   # 前端测试
mvn -o package -DskipTests && java -jar target/ecom-aftersales-agent-0.0.1-SNAPSHOT.jar
curl -N "http://localhost:8123/api/ai/agent/chat?chatId=demo&message=吊牌剪了还能退吗"
```
