# 测试用例清单

> 项目：电商售后智能客服平台（ecom-aftersales-agent）  
> 基线版本：Git commit `a423162`（工作区源码未做任何修改）  
> 测试日期：2026-10-18  
> 用例总数：126 条（后端 97 条 / 前端 29 条）

## 1. 说明

### 1.1 测试范围

| 层 | 覆盖对象 | 主要验证点 |
|---|---|---|
| 后端 | `agent/` 状态机、ReAct、工具调用、SSE | 状态迁移、终止语义、最大步数、异常兜底、progress/[DONE] 协议 |
| 后端 | `tools/` 文件、PDF、联网搜索、规则检索、工具注册 | 正常路径、错误兜底、路径安全、工具集合与 schema |
| 后端 | `rag/` 文档加载、切分、查询改写、空检索兜底 | topic 元数据、切分、改写、转人工话术 |
| 后端 | `app/` 售后客服应用 | 多轮记忆、会话隔离、RAG 注入、结构化输出、工具/MCP 接线 |
| 后端 | `controller/`、`config/`、`chatmemory/` | 同步/SSE 接口、健康检查、CORS、文件记忆 |
| 前端 | `ChatRoom.vue`、`api/index.js`、`router` | Markdown 渲染与 XSS 转义、SSE 封装、路由契约 |

**未包含**：真实大模型/联网调用、MCP 服务端执行、浏览器端到端与视觉验收。原因见《测试报告》第 7 节。

### 1.2 执行方式

- 后端：JUnit 5 + Mockito，运行 `mvn test`（或本机离线环境下的 JUnit Platform Runner）。全部用例不依赖 API Key，不产生模型调用费用。
- 前端：Node 原生脚本（无额外依赖），在 `ecom-frontend` 下执行 `node tests/run.mjs`。

### 1.3 结果口径

- **通过**：断言全部成立，符合 AI_CONTEXT/README 约定。
- **失败**：用例描述了期望的正确行为，当前实现未满足。本轮修复前有 6 条失败用例（BUG-01 ~ BUG-05），修复后已全部转绿，见第 6 节。
- 编号规则：`TC-<模块>-<序号>`；前端用例为 `TC-FE-<序号>`。

## 5. 未执行用例与原因

| 对象 | 原因 |
|---|---|
| 原有 7 个测试类（其中 6 个 `@SpringBootTest`，`AftersalesAppTest`、`AftersalesAgentTest`、`WebSearchToolTest` 等） | 会启动完整 Spring 容器：加载知识库逐片段调用模型做关键词增强并向量化（约 17 次模型调用），且部分用例调用真实 DashScope/SearchAPI；产生费用、依赖本地密钥、结果不稳定。本次以 Mock 替代，未执行原测试类。 |
| `ecom-mcp-server` 模块用例 | 该模块测试依赖（Spring Boot 3.4.5）在本机离线仓库中缺失，无法编译执行；原 `ImageSearchTool` 的 Pexels Key 硬编码问题已于 2026-10-18 改为 SearchAPI，见 docs/changes 第 8 节。 |
| 浏览器端交互/视觉验收 | 本环境无浏览器驱动；`npm run build` 也因沙箱阻止 esbuild 子进程（spawn EPERM）未能执行。前端逻辑改用 Node 直接验证。 |
